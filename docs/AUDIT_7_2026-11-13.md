# Audit 7 (2026-11-13): vision + NLP, an end-to-end audit, SWOT, improvements and a second pass

**Request.** On 2026-11-12 the owner asked for these, in order:
1. Make NEXUS one vision + NLP multimodal model.
2. Take what is needed from the SEC filings price-impact project (the NLP project).
3. Make the whole project robust and audit every file.

Overnight the owner gave full authority until 14:00 IST on 2026-11-13, adding:
1. Finish every run.
2. Audit end to end, with a SWOT analysis.
3. Improve the project as the SWOT indicates.
4. Audit again.

**Standard.** As in audits 1-6:
* every number traces to a file;
* nothing may see the future;
* rules come before results;
* every selection trial is counted;
* nothing fails silently.

The sealed 2023+ period was not read. No frozen model, freeze record or forward-test log was changed. No scheduled task
was modified.

## Verdict

**The language branch is built, tested and audited, and it does not improve the forecast.**
* **E28** (pre-registered, D-053) added three blocks to the gated fusion of charts, indicators and classical text:
  * FinBERT news;
  * ChronoBERT-2010 filing vectors (68,853 filings, from a model that never read text after 2010);
  * an SEC price-impact expert trained on the SEC study's own labels.
* **The result is NOT KEPT.** The blocks beat a within-date placebo on 2017-18, +0.00023 [+0.00003, +0.00040], but not
  the six current blocks, -0.00029 [-0.00082, +0.00025]. The language is stock-specific but redundant with what the
  charts and indicators already carry.
* **The SEC study replicates inside NEXUS.** Filings predict whether a stock moves (validation AUC 0.656, against the
  study's locked 0.635), not which way (0.513).

**One real defect was found and fixed before it could matter.** The first E28 run's SEC expert read three availability
timestamps as numbers, which is calendar time (A-69).
* The fix and a single re-run were committed before the corrected result existed (D-054).
* The decision did not change.
* The project now refuses non-numeric model inputs and scans every model, including the five frozen ones, for
  calendar-time proxies (A-70).

**Pass 2 (section 7) found the project consistent.** Of the open items, one is the owner's: the scheduled task's
logon type (A-76).

## 5. SWOT

**Strengths**
* **Discipline.** Every keep decision was pre-registered, recomputed by an independent audit script and logged, failures
  included: 28 experiments, at most 681 counted selection trials on 2017-18.
* **Point in time throughout.** The checks are brute-forced:
  * filings by `available_utc`;
  * a text encoder that never read the evaluation years;
  * labels read only before 2019;
  * the sealed period never opened.
* **Reproducibility.**
  * Deterministic training (E28's BASE reproduced to the fifth decimal across runs).
  * Pinned model revisions; Colab pins equal to local; the notebook re-derives labels, indicators and the language
    branch.
  * The owner's Colab run reproduced E22, E23 and E25.
* **Operational integrity.**
  * Five frozen models are hash-verified.
  * The forward test is hash-chained and pushed publicly every night.
  * SPC monitoring; one command now audits the project (`run_all.py`).
* **What is real is measured and consistent across years:**
  * "will it move" (sideways AUROC 0.59-0.61; the SEC expert's move AUC 0.656);
  * a small cross-sectional rank IC (0.02-0.04 on validation and test);
  * calibrated probabilities.

**Weaknesses**
* **No direction edge, and no economic edge over buy-and-hold after costs.** Up-vs-down AUROC is 0.51-0.54 on
  validation and 0.49-0.51 on test. Language did not change this.
* **The 2017-18 validation block is exhausted.** Up to 681 trials have been made on it; another keep there would be
  weak evidence.
* **The language blocks have no live path** (no news feed; the expert needs the SEC study's event features), so they
  cannot enter the forward test.
* **News coverage shifts over time** (30% of training rows, 64% of validation rows). This is the likely reason FinBERT
  news hurt.
* **Guards were name-based until today** (A-69/A-70), and one notebook check could not fail (A-72) or always failed
  (A-77): checks that are never seen to fail are weak checks.
* **One laptop runs everything.** CPU-only (6 h to encode filings), Modern Standby, an Interactive-logon task (A-76).

**Opportunities**
* **Unread data.** The forward test accumulates clean out-of-sample evidence (about 120 sessions are needed). The sealed
  2023+ period gives one semi-confirmatory read.
* **Predict volatility, not direction.** What the models predict best is move versus no move (the fusion and the SEC
  expert). A pre-registered forward test of a sizing or stop rule driven by P(move) is a natural next study.
* **A live filing path.** EDGAR 8-K text (with the owner's User-Agent) through the same ChronoBERT cleaning and
  encoding would let `sec_tx`/`sec_impact` run live, and so enter a forward test.
* **Colab GPU.** It makes full re-encoding (minutes, not hours) and larger encoders practical. Fine-tuning a text
  encoder would need fresh evaluation years.

**Threats**
* **Overfitting through reuse.** Any further selection on 2017-18 or on the read test years.
* **Silent defects** in inputs that look plausible: the class A-69 belongs to.
* **Vendor and API drift.**
  * Yahoo against the vendor bars (v3_alpha at 1D/2D, D-049).
  * Gemini model retirements.
  * Hugging Face revisions (mitigated by pinning).
* **Operations.** Windows updates and sleep killing nightly runs (D-048, D-052); a missed session cannot be back-filled.

## 9. After the audit: the 07:00 run of 13 Nov (A-80, A-81, D-055)

Watching the nightly run was the last check, and it found two defects.

* **What happened.** At 07:00 IST Yahoo answered, and SPY already had the 2026-11-12 bar, so the preflight passed.
  Stock daily downloads, however, still ended on 2026-11-11 (files re-downloaded at 07:16 also ended there). v1.1 and v2
  forecast their first stock as of 2026-11-11, took that session's decision time, already passed, as the deadline and
  stopped after one ticker. Only market_e19 logged session 2026-11-12. The run then pushed the logs as usual and left
  the session unmarked for a retry.
* **Make-up.** By 10:30 IST Yahoo had the bar (checked with the forecaster's own download). The unchanged nightly runner
  was started at 10:35 IST, before the session's decision time (19:30 IST), and all five models logged session
  2026-11-12: 497 stocks each, 0 late rows, every chain intact. This is an on-time log, not a back-fill (D-055).
* **A-80 (High, fixed).** The preflight now checks freshness as well as reachability: at least 6 of 8 liquid stocks,
  downloaded the way the forecaster downloads them, must reach the expected session. It waits (60 x 90 s) until they
  do. Tested; probed live: 8/8 for 2026-11-12, 0/8 for 2026-11-13.
* **A-81 (Medium, fixed).** The forecasters' deadline was the earliest decision time over all forecasts, so one stale
  stock (halted, late data) anywhere in the list could stop the whole run. It is now the expected session's decision
  time. `tests/test_shadow_deadline.py` reproduces the old stop (it fails on the previous code) and passes on the fix.
  `kronos_forecast.py`, not in the nightly batch, had the same pattern and is fixed the same way.
* **Checks after the fixes.** `scripts/verify/run_all.py --full`: 10/10. 189 tests pass; 5 frozen models match; 24
  chained files intact (19 plus the five of session 2026-11-12); scorer hash unchanged; no calendar time in any input;
  lock, notebook and README checks pass; E28 audit 17/17. The make-up run's own nightly test suite also passed, and it
  pushed the logs (`3f4ae30`).
