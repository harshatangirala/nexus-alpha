# Audit 5 (2026-11-10): end-to-end review before the presentation and the paper

**Role and standard.** The work is reviewed as a chief audit officer at a systematic trading firm would review a
research platform before capital or publication. Five questions:
1. Can every number be traced to code and data?
2. Could anything have seen the future?
3. Were the rules fixed before the results?
4. Is the multiple testing accounted for?
5. Would the system fail silently?

**Scope.** Everything added on 2026-11-10 (D-046 to D-051), and the end-to-end chain it joins: data, features,
models, evaluation, forward test, dashboard, reproduction, integrations, security and licensing.

## Verdict

**Fit for presentation and as the code base of a working paper, with the stated limits.**
* **Controls.** Each new component is pre-registered, point-in-time and tested, and its forward test is
  hash-chained.
* **Defects.** The ten defects found today are fixed (A-53 to A-62 below); none affected a logged forecast.
* **What the evidence supports.** Volatility-regime prediction and a 20-session market read. Small cross-sectional
  ranking gains are kept for forward testing. No validated stock-direction or trading edge.

## What was verified, with evidence

* **Traceability.**
  * The Mission Control evidence board quotes each number verbatim from its source document
    (`tests/test_dashboard.py`).
  * E25's tables were checked against `experiments/20261110T144028_e25_alpha158_951bbf/metrics.json`.
  * E25's baseline set reproduces E07's validation log losses to five decimals (1.03472, 1.05250, 1.06277,
    1.06705).
* **Independent implementation.**
  * Alpha158 matches Qlib 0.9.7's own engine: identical definitions on 122,797 stock-days; the correlation
    differences are fully explained by Qlib's float32 inputs.
  * The options fallback matches OpenBB's transform exactly.
* **No look-ahead.**
  * Alpha158 is causal (tested). `features_at` refuses stale or short bar histories (tested).
  * Every new development read goes through the sealed readers. The live-parity check reads vendor bars only to
    2022-12-30.
  * The sealed 2023+ period has never been opened (no holdout access log exists).
* **Rules before results.**
  * E25 written at 14:35, run at 14:40; the manifest holds the text's SHA-256, unchanged since.
  * E26 and E27 written before any snapshot or committee run.
  * D-051 written before any 20D outcome.
  * D-049's deviation (per-horizon deployment) is disclosed and outcome-blind.
* **Forward test.**

    time.
  * The runner is byte-clean and run through cmd.exe as the task runs it.
  * New steps are non-fatal and do not gate the done marker.
* **Reproduction.**
  * The Colab one-pass now re-runs E25 too.

* **Security and licensing.**

* **Tests.** The full suite passes (see the commit), and it runs every night.

## Residual risks (stated, not fixable in code)

1. **Survivorship.** The universe is today's survivors from one vendor.
2. **Vendor shift live.** Yahoo's volume is not the vendor's (`docs/LIMITATIONS.md` item 27). It was measured for
   Alpha158, not for the volume parts of F0.
3. **A reused selection block.** 2017-18 carries up to about 665 trials; only the forward test and the sealed period
   are clean.
4. **External services.** Yahoo, SEC, CBOE (via OpenBB) and Google can fail or throttle. Every nightly step degrades
   to "not logged", never to a wrong log.
5. **The forward test is young.** Five models, 1-3 sessions each. Nothing can be claimed for months.
